# АгроМаркет (React)

Учебный проект: каталог фермерских продуктов на React + Vite. Данные приходят с собственного Express-сервера (репозиторий `agromarket-server`), заявки из формы отправляются туда же методом POST.

## Запуск

1. В папке `agromarket-server`: `npm install`, затем `npm run dev` (http://localhost:3000)
2. В папке `agromarket-react`: `npm install`, затем `npm run dev`
3. Открыть http://localhost:5173

> json-server (лаб. 3) больше не нужен. Файл `db.json` остался в репозитории как исходные данные — его копия лежит в `agromarket-server/data/`.

## Лабораторная 7 — вход и защищённые запросы

- `src/api.js`: адрес API (`API_URL`) объявлен в одном месте, а функция `apiFetch` добавляет к запросам токен (`Authorization: Bearer ...`), разбирает JSON и превращает ошибки API в исключения. Если сервер отвечает 401 на запрос с токеном (токен истёк или подделан), токен удаляется и страница перезагружается.
- `components/LoginForm.jsx`: одна форма для входа и регистрации, режим переключается кнопкой.
- `components/AddProductForm.jsx`: форма нового товара, видна только администратору (`user.role === 'admin'`). Показ формы только удобство: настоящая проверка прав выполняется на сервере.
- `App.jsx`: состояние `user` хранится в localStorage (токен и данные пользователя), при открытии страницы токен проверяется запросом `GET /api/auth/me`, кнопка «Выйти» удаляет токен.
- `ContactForm.jsx` и `App.jsx` берут адрес API из `api.js`.

Администратор создаётся на сервере командой `npm run db:init` (логин и пароль из `.env`). Новые пользователи через регистрацию получают роль `user` и формы товара не видят.

## Лабораторная 5 — что изменилось в React

- `App.jsx`: адрес запросов сменился с `http://localhost:3001/products` (json-server) на `http://localhost:3000/api/products` (Express).
- `ContactForm.jsx`: вместо `alert` форма отправляет данные на `POST /api/orders`. Обрабатываются ответы `201` (заявка принята), `400` (ошибка валидации от сервера) и недоступность сервера. Пока идёт запрос, кнопка блокируется и показывает «Отправка…».
- Поле «Объём заказа» переименовано с `volume` в `quantity` — под это имя настроена валидация на сервере.

## Лабораторная 4 — вёрстка

### Box model карточки (часть 1)
- content: ≈ 255 px (на экране 1280 px), padding: 16 px с каждой стороны, border: 1 px, margin: 0
- итоговая ширина карточки на экране: ≈ 289 px
- с `box-sizing: border-box` итоговая ширина **не изменилась**: у карточки нет заданной `width`, она автоматически растягивается на всю колонку сетки. Разница видна, когда ширина задана явно: при `width: 300px` без `border-box` карточка заняла бы 300 + 32 (padding) + 2 (border) = 334 px, а с `border-box` — ровно 300 px.
- в дереве элементов `<div>` совсем немного (`#root` и контейнер сетки карточек), шапка, каталог и подвал распознаются по тегам `<header>`, `<main>`, `<footer>`.

### repeat(4, 1fr) на узком экране (часть 4)
Число колонок остаётся равным четырём при любой ширине окна, поэтому на ~500 px карточки сжимаются до узких столбиков: названия переносятся по буквам и слогам, кнопки и цены не помещаются, страница может получить горизонтальную прокрутку.

### auto-fit vs auto-fill (часть 4)
При `auto-fit` пустые колонки схлопываются и 1–2 найденные карточки растягиваются на всю ширину сетки, а при `auto-fill` пустые колонки сохраняются и карточки остаются обычной ширины. Выбран `auto-fit`.

### Форма заявки (часть 6)
Поля `email`, `tel`, `number` (min=10), `date`, атрибут `required`. Браузер сам блокирует отправку пустой формы, email без «@» и объём меньше 10 кг. Неверные поля подсвечиваются красной рамкой через `:user-invalid`.

## Переменные окружения

Адрес API задаётся переменной `VITE_API_URL`. Локально она лежит в `.env.development` (`http://localhost:3000/api`), на хостинге задаётся в настройках сборки. Если переменной нет, используется `http://localhost:3000/api`. Файлы `.env*` читаются только при старте Vite, поэтому после изменения нужно перезапустить `npm run dev`.

Переменные с префиксом `VITE_` подставляются прямо в собранный JavaScript и видны любому посетителю сайта, поэтому секреты (пароли, `JWT_SECRET`) в них хранить нельзя.

## CI

Workflow `.github/workflows/ci.yml` на каждый Pull Request и push в `main` выполняет `npm ci`, `npm run lint` и `npm run build`: в `main` не попадёт код, который не собирается.

## Лабораторная 9 — деплой

Сайт раздаётся Vercel как набор статических файлов из `dist/`; API — на Render, база — в Neon (см. README в `agromarket-server`).

- `vercel.json` — правило *rewrites*: любой путь, для которого нет файла (`/login`, `/admin`, обновление страницы по F5), отдаёт `index.html`, дальше маршрутизацию берёт React. Без него Vercel отвечал бы 404 на прямые ссылки.
- `VITE_API_URL` задаётся в Vercel → Settings → Environment Variables (`https://agromarket-api-kaplinnikitos-alt.onrender.com/api`). Значение вписывается в JavaScript **при сборке** — после изменения переменной нужен *Redeploy*. Образец — `.env.example`.
- Если в продакшене сайт ходит на `localhost:3000` — переменная не была задана до сборки. Если в консоли ошибка CORS — адрес сайта не добавлен в `CORS_ORIGIN` на Render (символ в символ, без `/` в конце).
- CI (`.github/workflows/ci.yml`): `npm ci` → `npm run lint` → `npm run build` на каждый PR и push в `main`; в защите ветки `main` обязательная проверка — `build`.
- Preview-версия Vercel для PR получает адрес вида `agromarket-git-ветка-….vercel.app`, которого нет в `CORS_ORIGIN`, поэтому каталог на ней не загружается — это защита CORS, а не поломка.
- Бонусы: подсказка «Сервер просыпается…», если каталог грузится дольше 3 секунд (`src/useSlowHint.js`); кнопки-фильтры категорий над каталогом из `GET /api/categories` (если эндпоинта нет, фильтров просто не видно).
